# 邮箱连接代理

在「设置 → 账户 → 添加或编辑邮箱」的「邮箱连接代理」中选择 HTTP CONNECT 或 SOCKS5，填写主机、端口及可选的用户名、密码，然后保存。每个邮箱独立配置，同一个代理用于该账户的 IMAP 收信及 SMTP 发信；选择「直接连接」即可关闭代理。

编辑时密码留空会保留原密码；勾选「清除已保存的密码」可移除认证密码。密码使用现有的 ENCRYPTION_KEY 加密存储，账户 API 只返回是否已保存密码。保存代理配置会自动重连邮箱。

代理地址由 MailFlow 后端访问。Docker 部署中的 127.0.0.1 指向后端容器自身；请填写容器能访问的宿主机或局域网地址。使用局域网、回环或其他私有地址的代理时，需要管理员在安全设置中启用「允许私有主机」。代理端口可以在 1–65535 范围内配置，无需启用非标准邮件端口。

邮件服务器和代理服务器的 DNS 均由后端解析，并固定到校验过的 IP；不使用代理侧 DNS。邮件 TLS 仍按原来的邮件主机名验证证书。代理失败会报错，不会退回直连。代理连接有超时限制。

该配置只覆盖账户的 IMAP/SMTP 连接；OAuth 授权页面和令牌刷新、联系人同步、AI 等 HTTP 服务继续使用原有网络连接。

当前锁定的 imapflow 1.7.8 对 SOCKS5 用户名和密码缺少 URL 解码。backend/scripts/patch-imap-proxy.cjs 在安装依赖时将这两个赋值改为使用库已有的解码函数；Docker 构建同样执行该修复。真实 IMAP/SMTP 代理握手测试包含特殊字符密码，升级依赖时应保留这些回归检查。库结构变化导致补丁无法匹配时，安装会明确失败，以便审查兼容性。
