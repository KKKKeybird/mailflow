# 反垃圾判定、训练与 Gmail 代理

MailFlow 的本地学习模型与 Gmail 服务端的垃圾邮件判定相互独立。手动标记会通过 IMAP 移到映射的垃圾邮件文件夹，并记录本地训练反馈；本地训练不能保证 Gmail 自身以后如何处理同类邮件。

## 状态与默认策略

- “模型格式版本 1”是数据/算法格式版本，不是训练次数；反馈增加时它不会递增。
- 少于 50 条训练记录时仅使用规则。
- 不再按固定 60%/40% 或 20%/80% 混合。模型优先，规则作为回退。
- 模型须包含正常和垃圾两类训练，当前邮件至少 20% 的不同文本词见于词库，且至少两个不同词有与判定方向一致的显著倾向（单词累计至少出现 3 次、对数似然贡献绝对值至少 0.5）。重复同一个词不能凑足这两个特征。
- 满足以上条件时，模型概率达到垃圾阈值则直接采用；低于 `1 - 垃圾阈值` 则直接认定正常。其余情况使用规则分。该证据门槛是启发式保护，不代表经过统计校准的准确率。
- 默认最终分数达到 0.85 才标记垃圾，达到 0.95 且训练至少 50 条、垃圾邮件文件夹已映射时才自动移走。模型的明确正常判定不会再被规则覆盖。
- 例如 108 条样本、两类训练和文本证据充足时，模型概率 0.99 会直接作为最终分数，不再被低规则分拉低。仅有垃圾训练时不会信任模型的极端概率，需要补充“非垃圾”反馈。
- 新邮件分类使用用户已保存的垃圾分类/自动移动阈值。未配置或无效值使用默认值；默认阈值不变。
- 分类详情记录策略版本、使用模型或规则的原因、文本覆盖率及支持判定的不同词数量。历史判定保留原始策略，不会自动改写。
- 重新索引/历史回填只分类、不自动批量移动；`spam_details.autoMoveDeferred` 记录是否因回填而延后。

## 标记后短暂重新出现

手动标记保留约 4.5 秒撤销窗口，之后才发送 IMAP 移动请求。慢速代理会进一步延长服务器确认时间。前端对来源文件夹保留待移动保护，覆盖撤销窗口、请求执行及短暂旧响应；进入目标垃圾邮件文件夹仍能正常看见邮件。撤销或失败会解除保护并恢复来源邮件。

## 自动移动与代理

自动分类传给移动适配器的摘要只有账号 ID 和邮箱地址。适配器必须使用本次同步的完整账号配置（IMAP 主机、认证与代理）建立连接；否则复用现有连接可能成功，但需要新建连接时会因配置缺失而失败。此修复保留完整账号配置及每账号移动并发限制。

分类详情保存本次使用的阈值与样本数，便于区分“模型分数不足”和“IMAP 移动失败”。定位失败可查看 `spam auto-move failed`、`IMAP move for /spam failed` 和 `spam incremental training failed` 日志；分享日志前移除凭据和邮件内容。

## 参考与适用边界

- [SpamAssassin 官方配置说明](https://github.com/apache/spamassassin/blob/trunk/lib/Mail/SpamAssassin/Conf.pm)：`bayes_min_ham_num` / `bayes_min_spam_num` 默认各 200，强调正常与垃圾双向训练后才启用统计分类。
- [Rspamd 官方统计分类文档](https://github.com/rspamd/rspamd.com/blob/master/doc/configuration/statistic.md)：采用 OSB 稀疏双词组与逆卡方组合，示例配置包含 `min_tokens = 11`、`min_learns = 200`，以及自动学习时的类别平衡检查。

本 fork 参考双向训练、证据门槛与保守回退原则，继续使用现有逐用户 MNB 词库；没有移植上述产品的完整算法，也未把这些产品的默认门槛照搬到只有少量个人反馈的场景。当前 50 条总训练门槛及文本证据门槛属于本地启发式，需要用独立标注邮件集验证实际误判率；模型概率不是校准后的准确率。自动判定继续不反向训练，防止误判自我强化。词组模型或概率校准需要单独的数据验证和词库兼容方案。
